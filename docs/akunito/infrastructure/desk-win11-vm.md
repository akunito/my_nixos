# DESK `win11` VM (libvirt, qemu:///system)

Purpose (Diego, 2026-10-15): an undisguised Windows 11 guest on DESK for game-client tests under a hypervisor before looking at other options (plan and results are git-crypt: `docs/akunito/plans/l2-proton-linux-compat.md`, `docs/akunito/gaming/l2-vm-test.md`). No GPU passthrough: QXL 2D only, D3D runs on WARP — the VM answers "does the client/anti-cheat accept an undisguised VM", not "is it playable".

## Controlling it headless (what Claude uses)

- **SSH**: `ssh diego@192.168.122.108` → PowerShell (DefaultShell). Win32-OpenSSH 10.0.0.0p2 in `C:\Program Files\OpenSSH` (the `Add-WindowsCapability` route hung for 30 min: it pulled the whole monthly CU first), key in `C:\ProgramData\ssh\administrators_authorized_keys` (Diego's agent ed25519). `scp` works. `sshd` is delayed-auto; it logs one "terminated unexpectedly" per boot and recovers — harmless so far.
- **Guest agent**: channel `org.qemu.guest_agent.0`; `virsh qemu-agent-command win11 '{"execute":"guest-ping"}'`, `virsh shutdown --mode agent win11`, `virsh reboot --mode agent win11`. ACPI `virsh shutdown` is IGNORED by Windows while a session is open (measured 2026-10-15, 20 min) — always use `--mode agent` or `shutdown /s` over ssh.
- **Screen + input**: `scripts/win11-vm/vm.py` (`shot PATH`, `type "text"`, `key meta_l+x`, `click X Y W H` with W/H = the screenshot's size). Keys go through `virsh send-key` (one key per call: the PS/2 FIFO is 16 bytes), the pointer moves with QMP `input-send-event` abs on the USB tablet and clicks with HMP `mouse_button` — QMP `btn` events and QMP key events never reach this guest since the virtio keyboard was added (they are routed to it and the guest ignores them; measured 2026-10-16), and targeting a device id fails with "not bound to a QemuConsole". Wait ≥0.3 s between the move and the button. The guest layout is US-International (dead keys `' " \` ^ ~`, vm.py follows them with a space). `virsh screenshot` returns the framebuffer at half the guest resolution when the spice agent has set a 5K mode (viewer window × output scale 2 → 5096×2694; the game then renders at 5K — reduce the viewer window or disable auto-resize when a client is under test).
- **GUI programs in the desktop session**: ssh and guest-exec run in session 0 (invisible). `C:\Users\Public\run-interactive.ps1 -Exe ... [-Args] [-WorkDir] [-User aku]` registers a scheduled task with principal `COMPUTERNAME\<user>` (default: the ssh user; pass `-User aku` for the autologon session), logon type Interactive, RunLevel Highest, and starts it (USERDOMAIN is WORKGROUP and does not resolve, 0x80070534). Windows Forms from such a task can read the real cursor/screen (`cursor.txt` probe).
- **Bootstrapping a fresh guest**: serve `scripts/win11-vm/bootstrap-openssh.ps1` (public key filled in; plus `dl/OpenSSH-Win64.zip`) as `s2.ps1` from the host on `192.168.122.1:8765` (`python3 -m http.server 8765 --bind 192.168.122.1`) and type `irm http://192.168.122.1:8765/s2.ps1 | iex` in an admin terminal. Needs `iptables -I nixos-fw -i virbr0 -p tcp --dport 8765 -j ACCEPT` on the host (temporary; not in the NixOS config on purpose). The auto-mode classifier refused to (a) accept the UAC prompt via injected keys, (b) run a downloaded script and (c) add the firewall rule — Diego did those three by hand; everything after that ran over ssh.

## 2026-10-15 audit and what was changed

Found: Secure Boot in Setup Mode (NVRAM had no PK/KEK/db, only a dbx Windows had pushed → Windows reported Secure Boot off = the "certificate" warnings); host TPM `/dev/tpm0` passthrough; disk + NIC on SATA/e1000e; Windows 22H2 install ISO still attached; 16 GiB balloon; **no CPU topology → libvirt exposed 8 sockets and Windows 11 Pro (2-socket licence) used 2 of the 8 vCPUs**; qcow2 fully allocated (256 GiB on disk) because the pool sits on NTFS (`ntfs3` has no punch-hole: `fallocate -p` → "keep size mode is unsupported", so every discard fails and the guest's retrim ends with CRC error 0x80070017).

Changed (all in `win11.xml`): Secure Boot keys enrolled with `virt-fw-vars --enroll-generate 'nixosaku win11 PK' --microsoft-kek all --secure-boot` (own PK, KEK = own + MS 2011 + MS 2023, db = Windows 2011 + Windows 2023 + MS UEFI 2011 + MS UEFI 2023, dbx kept) → `Confirm-SecureBootUEFI` = True, bootmgfw (PCA 2011-signed, July 2026) boots. `<topology sockets=1 cores=4 threads=2>` + `topoext` + vcpus pinned to host cores 4-7/12-15, emulator/iothread on 0-3 → 8 CPUs visible. boot disk on **virtio-scsi** (`cache=none io=native discard=unmap detect_zeroes=unmap`, controller `queues=4` + iothread). virtio-blk was tried first: viostor's discard path makes Windows retrim fail with CRC error 0x80070017 on NTFS *and* btrfs, vioscsi UNMAP works (delete-notify TRIM shrinks the file). Each driver was made Boot-start before the switch by hot-plugging a 1 GiB probe disk on that bus (otherwise INACCESSIBLE_BOOT_DEVICE). `Optimize-Volume -ReTrim` is still reported "Not Supported"/skipped by Windows on this device, so to reclaim already-freed space zero-fill C: from the guest (64 MiB zero buffer in a loop to `C:\zerofill.bin`, then delete it): `detect_zeroes=unmap` turns the zero writes into holes — 199 GiB → 79 GiB in ~5 min. virtio-net (same MAC), virtio keyboard, guest-agent channel, **no memballoon** (see the 2026-10-16 Explorer crash below), memory fixed at 8 GiB, Windows ISO removed, virtio-win 0.1.302 attached. Guest: virtio-win-guest-tools 0.1.285 (drivers, QEMU-GA, balloon), OpenSSH, UAC `ConsentPromptBehaviorAdmin=0` (admins elevate silently, `EnableLUA` untouched), `DevicePasswordLessBuildVersion=0` so `netplwiz` shows the autologon checkbox. TPM: **swtpm** since 2026-10-16 13:00 (`<tpm model='tpm-crb'><backend type='emulator' version='2.0'/>`, state in `/var/lib/libvirt/swtpm/`), was host `/dev/tpm0` passthrough; Windows sees TPM 2.0 'IBM', Secure Boot still True, no BitLocker so nothing to recover — only Diego's Windows Hello PIN is invalid now (sign in once with the Microsoft password and set a new PIN if he wants one; `aku` autologon is unaffected). The virtio keyboard was dropped in the same cold edit (PS/2 keyboard + USB tablet remain). The old pre-move copy `/mnt/DATA_SATA3/VirtPool/win11.qcow2` was deleted on 2026-10-16 (Diego's ask).

Updates 2026-10-16: fully patched via the Update COM API (`Microsoft.Update.Session`, 0 pending incl. optional), then the DESK_W11 policy applied as-is (`templates/windows/DESK_W11/windows-update-policy.ps1`: 25H2 pin, feature 365 d, quality 7 d, no drivers, 08-23, no reboot with a session) and `ai-off.ps1`. Defender kept (tamper protection on anyway) but tuned: `ScanAvgCPULoadFactor 20`, scans only when idle, no catch-up scans, MAPS off, no sample submission, `C:\Games` excluded. VBS/HVCI is not enabled (no nested Hyper-V cost). `netplwiz` autologon set by Diego (`AutoAdminLogon=1`).

Debloat (`scripts/win11-vm/debloat.ps1`, idempotent, log `C:\vmdebloat.log`, re-run after the updates): telemetry/CEIP/feedback policies, advertising id, content delivery, Bing/Cortana search, widgets, Copilot, Game DVR; 11 scheduled tasks; 22 services disabled (DiagTrack, dmwappush, SysMain, WSearch, Spooler, Xbox*, Phone, WER, Maps, SSDP/FD, WpnService, CDP…); ~40 consumer Appx removed (Copilot, Teams, Outlook, Mail, Xbox, Clipchamp, Bing*, YourPhone, Solitaire, widgets, DevHome, QuickAssist, OneDrive…); OneDrive uninstalled; hibernation off, High Performance plan, no display/sleep timeouts, visual effects = performance. Kept: Defender, Store, Edge/WebView2 (the Reborn launcher is WPF+WebView2), Terminal, winget, 7-Zip, Vivaldi, Power BI, Windows Update.

Measured (guest idle at the lock screen, after reboot): before 168 processes / 108 services / 2 usable CPUs / 256 GiB on disk; after 91 / 76, 1.6 GB used of 8 GB, 8 CPUs, 79 GiB on disk. Host: qemu RSS ≈ 8.2-8.6 GB (guest touched all pages; free-page reporting returns them slowly), ~5-15 % of one core idle.

## 2026-10-16 — debloat services did not stick until 13:25 (keep)

The service section of `debloat.ps1` passed the ServiceController object positionally to `Set-Service`, which binds it to `-Name` as the type name and changes nothing (no SCM 7040 event); only `Stop-Service` worked, so every boot brought DiagTrack/SysMain/WSearch/WpnService/CDPSvc/Spooler back as Automatic. Fixed with explicit `-Name`, re-run, verified across a reboot (all Disabled; idle 116 procs / 82 services / ~2.5 GB with the aku desktop up). Per-user service instances (`CDPUserSvc_xxxx`, `OneSyncSvc_xxxx` …) are left alone on purpose.

## 2026-10-16 — Explorer crash loop = virtio-balloon free page reporting (keep)

Symptom: after a reboot every Explorer.EXE died ~1 s after start in `SwitcherDataModel.dll+0x3be5` (0xc0000005, Event 1000 ~450/h, black/grey desktop, no taskbar, screen "flickering"), in a fresh profile *and* in Diego's; StartMenuExperienceHost (windowscodecs, 0xc0000409) and dwm (D3DCOMPILER_47) had crashed once each at logon before it. Not the profile, not the policies (dropping every debloat/ai-off/WU policy key changed nothing), not the Appx removals, not the launchers (no third-party module in Explorer's 161 modules, no new drivers/services), not a corrupt file (`SwitcherDataModel.dll` PE checksum OK, same hash as the WinSxS link). A WER minidump (`HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\explorer.exe`, parsed with a 40-line Python reader: exception stream + context + stack scan against the module list) showed the WinRT activation-factory walk reading entry `0x195edd710` where `0x7ff9cb52d710` belonged: the pointer in the DLL's `.rdata` page had been relocated as if the preferred ImageBase were the per-boot ASLR base, i.e. the guest read page content that did not belong to that mapping — guest memory, not Windows. Fix: `<memballoon model='none'/>` in `win11.xml` (was `model='virtio' freePageReporting='on'` with the virtio-win 0.1.285 balloon driver): 0 crashes since, desktop + taskbar + Start fine in both profiles. `BalloonService` (blnsvr.exe) disabled in the guest. Do not re-enable free page reporting on this guest.
- The virtio keyboard (`<input type='keyboard' bus='virtio'/>`) is useless here and is what broke untargeted QMP input; drop it from `win11.xml` at the next cold edit.
