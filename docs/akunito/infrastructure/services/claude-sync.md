# claude-sync — Claude Code state across DESK, LAPTOP_X13 and DESK_W11

Keeps `~/.claude` (memory, skills, commands, plans, agents, session
transcripts) identical on every machine without manual syncing, through a hub
on VPS_PROD that is always on. Designed 2026-09-13 (interview in the session
that shipped it); the old manual `/sync-claude-config` rsync command is retired.

## What syncs, how

| Data | Channel | Merge rule |
|---|---|---|
| `projects/*/memory/`, `skills/`, `commands/`, `plans/`, `agents/`, `CLAUDE.md`, `history.jsonl` | git repo rooted at `~/.claude` (whitelist `.gitignore`), remote `hub` = `~/claude-sync/state.git` on the VPS | 3-way merge. `MEMORY.md` and `history.jsonl` are `merge=union` (both sides' lines kept). Any other conflict keeps BOTH versions: hub copy as the file, local copy as `<file>.conflict-<MACHINE>`; the SessionStart hook then asks Claude to merge them. |
| `projects/<key>/<uuid>.jsonl`, `projects/<key>/<uuid>/tool-results/`, `tasks/<uuid>/` | rsync, additive both ways (`--update` on pull, never `--delete`) to `~/claude-sync/sessions/` | Single writer per session: `<uuid>.owner` names the machine that created it. Only the owner pushes it. Another machine resumes it through `--fork-session` (new UUID, original untouched). |
| `file-history/` (rewind checkpoints), `todos/`, `sessions/` (runtime pids), `.credentials.json`, `settings.json`, `mcp-env`, caches | not synced | Per machine. Rewind only works on the machine that made the edits. `settings.json` is generated by Nix on every machine anyway. |
| `plugins/` | not synced (v1) | Reinstall with `claude plugin` if a machine lacks one. |

Retention: `cleanupPeriodDays = 365` on every client (Nix writes it into
`settings.json`); the hub deletes at 364 days so nothing deleted locally is
pulled back.

## Automation (all from Nix, flag `claudeSyncEnable`)

- **SessionStart hook** (`startup|resume|fork`): `claude-sync pull` synchronously
  (bounded to 45 s) so memory is current before Claude reads it. Injects context
  when `*.conflict-*` files are pending or when a foreign session was resumed
  without a fork.
- **Stop hook** (every turn): background `claude-sync push` of the current
  transcript + state commit/push. Rebooting DESK mid-session loses at most the
  in-flight turn.
- **SessionEnd hook** (1.5 s budget): same push in the background, plus a
  desktop notification if the project's git tree has uncommitted or unpushed
  changes — the session travels, the code does not.
- **`claude` wrapper** (`lib.hiPrio`, in PATH before the real binary): pulls
  first so `--continue` and the `/resume` picker see hub sessions, then adds
  `--fork-session` automatically when `-c` / `-r <uuid>` targets a session
  owned by another machine.
- **systemd user timer** `claude-sync.timer` every 15 min: full two-way sync,
  covers crashes, hand-edited skills and anything the hooks missed.
- **Hub timer** (root, daily 05:20): retention, Telegram alert on the Infra
  Alerts group when conflict files appear in the state repo or a machine has
  not pushed for 14 days, `git gc`.

Local warnings (notify-send): memory conflict saved, foreign session resumed
without fork, unpushed code on exit, hub unreachable for 6 h while trying.

## Edge cases and answers

- **Two sessions open at once on different machines** — different UUIDs, no
  conflict. Both push; the state repo merges; `MEMORY.md` union-merges.
- **Same session resumed on two machines** — prevented by the wrapper (fork).
  If bypassed (IDE, `/resume` picker, `--bare`), the hook warns, the foreign
  machine never pushes that file, and the user reopens with `--fork-session`.
- **Same memory file edited on two machines in the same window** — both
  versions kept, alert, Claude merges next session. Nothing is lost.
- **Hub down / offline** — everything keeps working locally; hooks time out
  quietly; the timer retries; local warning after 6 h.
- **Machine off for weeks** — fine; first session start pulls everything.
  Sessions older than 365 days will not come back.
- **DESK and DESK_W11 are the same box** — never on at once, but they behave
  like two machines: each has its own key, owner tag and `ENV_PROFILE`.
- **Project keys are paths** — Claude derives `projects/<key>` from the cwd,
  so every machine must run the same user (`akunito`) with repos at the same
  paths (`/home/akunito/.dotfiles`, `/home/akunito/Nextcloud/...`). On WSL,
  `~/Nextcloud` must be a symlink to the Windows Nextcloud folder.

## Security

Each client has a passphrase-less key at `~/.config/claude-sync/key`
(generated by `claude-sync init`, never in `~/.ssh`). Its public half is
listed in `claudeSyncHubKeys` in the VPS profile with
`restrict,command="claude-sync-shell"`: the key can only rsync into
`claude-sync/sessions|heartbeat` without `--delete`, and speak git to
`state.git`. No shell, no forwarding, no sudo. Transcripts contain command
output (sometimes tokens): the hub lives in the VPS home (0700, LUKS),
reachable only over Tailscale, outside restic.

## Bootstrapping a machine

1. Enable `claudeSyncEnable = true` in its profile, deploy (`sync-user.sh` is
   enough for an existing machine).
2. `claude-sync init` — generates the key, prints the public key.
3. Add the public key to `claudeSyncHubKeys` in `profiles/VPS_PROD-config.nix`,
   commit, push, deploy VPS_PROD (`install.sh ... VPS_PROD -s -u -d`).
4. `claude-sync sync` — merges the machine's existing memory with the hub
   (unrelated histories allowed; conflicts kept both ways), pulls sessions.
5. `claude-sync status` — reachable: yes, conflicts: none.
6. Routine pushes only cover sessions modified in the last 3 days
   (`PUSH_WINDOW_DAYS`). To make a machine's whole history resumable elsewhere
   once: `PUSH_WINDOW_DAYS=90 claude-sync push` (DESK did this on 2026-09-13).

Bootstrapped 2026-09-13: hub deployed on VPS_PROD, DESK (168 memories) and
LAPTOP_X13 (4 stale memories, merged without conflict) in sync, timers active.

## Operating

```bash
claude-sync status            # reachability, pending conflicts, owned sessions
claude-sync sync              # force a full two-way sync now
claude-sync pull|push         # one direction
claude --resume <uuid>        # wrapper forks automatically if the session is foreign
tail ~/.local/state/claude-sync/log
systemctl --user list-timers claude-sync.timer
# hub
ssh -p 56777 akunito@100.64.0.6 'du -sh ~/claude-sync/*; ls -la ~/claude-sync/heartbeat'
sudo systemctl start claude-sync-hub-maintenance   # on the VPS, run the daily job now
```

Merging a conflict by hand: keep every fact from both files in the base file,
delete the `.conflict-*` file, commit happens automatically at the next sync.
