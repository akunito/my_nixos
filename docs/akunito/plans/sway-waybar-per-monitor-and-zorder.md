# Sway desktop via sway-apps: per-monitor Waybar, stacking, monitors, persistence

**Status 2026-10-14: SWAY-1..14 implemented, merged and deployed on DESK (Diego verified Waybar per monitor, templates/sizes, fullscreen auto-all, Alt-drag, Hyper+wheel, pin, peek live); X13 deployed. SWAY-15 Hyper+Tab overview implemented 2026-10-14 (resident GTK4 layer-shell `sway-apps-overview`, cached thumbnails because wlroots 0.19 has no per-toplevel capture source; 43-56 ms to first paint in nested sway, ~95 MB). SWAY-16 Spacing (gaps + bar margins) done.** Deviations from the text below, measured during implementation:
- §2 WS mode does NOT use live CSS: Waybar's setupCss adds a CSS provider on every style reload/SIGUSR2 and never removes the old one, so a collapse rule could never be withdrawn. The mode rides on sway bar modes instead: `invisible` = hidden, `dock` = this monitor's workspaces (static `.mode-dock` rule), `overlay` = all workspaces (overlay preset remapped to dock's layer/exclusive zone). Any CSS change (sizes) restarts Waybar (tray-safe since SWAY-1). Bar blocks must be `bar { id X … }`, not `bar X { … }`. sway reports `fullscreen_mode: 1` on every workspace node: count children only.
- §3 peek is re-applied at the end of every arrange_root instead of inside arrange_children; pin is Hyper+middle click (Diego's choice), not a key.
- Output events never reload sway (a reload re-applies every `output` line and re-enabled a just-disabled output); placement freezes its snapshot only while a baseline output is missing.

Plane project **SWAY** (SWAY-1..14). Machines: DESK, LAPTOP_X13 (both `swayAppsEnable`). Interview with Diego 2026-10-14; decisions below are his, do not re-ask. AkuWM (`~/Projects/AkuWM`) was surveyed as the reference design; what it does and where we deliberately differ is noted per topic.

## 0. Cross-cutting architecture (do first, by the lead, before parallel work)

- **One event daemon.** `sway-apps watch` (already a user service bound to sway-session.target, today `output` events only) becomes the single sway-IPC subscriber for `output`, `workspace`, `window`, `binding`, `shutdown`, with a handler registry (`watch.register(kind, fn)`). Dispatch is IMMEDIATE; only the output handler keeps its debounce (today `watch.run` sleeps 1.5 s after EVERY line, watch.py:68-72 — must go). `window:title` events are dropped at the reader (Electron/terminals emit them constantly). Tree-dependent state (rolling per-output snapshot, effective bar visibility) is recomputed from one coalesced `get_tree` (dirty flag + ~200 ms timer), never per event. `Restart=always` + a `doctor` check: with the daemon down every feature hotkey is silently dead. No new daemons except the D-Bus tray watcher (§1), which must own a bus name.
- **Hotkeys without process spawn.** Feature hotkeys are `bindsym … nop sway-apps <verb>`; the daemon reacts to the `binding` event (verified: nop bindings emit it, commands/bind.c:644; payload = command, symbols, modifiers only — no output/container, so a verb costs one `get_outputs`/`get_tree`). Budget < 30 ms key→effect, measured. Anything that needs the container under the cursor stays a native sway command (the `z` wheel bindings). The CLI keeps the same verbs for scripts/ssh.
- **Registries landed by the lead BEFORE any parallel work** (so A–D never edit the same file): `FEATURE_CLIS` in cli.py (each feature ships `cli_<feature>.py`), the GUI panel list in gui/app.py, `watch.register`, a per-feature `SETTINGS_DEFAULTS` merge in state.py (nobody else edits state.py), the include lines and binding placeholders in swayfx-config.nix (`sway-apps-bars.conf`, outputs include swap, Hyper+Shift+H → nop, pin key, Hyper+wheel), both flag stubs in lib/defaults.nix (`swayWindowStacking`, the kanshi switch).
- **Hardware ids.** `make model serial` as today; when ALL three are `Unknown` (wlroots headless, some cheap panels) fall back to the connector name. The NSL (serial Unknown only) is unaffected. `SWAY_APPS_E2E=1` lifts the `HEADLESS*` filters in watch.signature and monitors.adopt_unknown so the e2e suite sees its outputs.
- **State.** Repo-backed profile JSON (`user/wm/sway/apps/<PROFILE>.json`) for choices meant to be versioned (defaults, templates, sizes, policies, output layout). Machine-local `~/.local/state/sway-apps/` for live state (bar visibility, window journal, loans). New keys get defaults in `state.py` so old JSON stays valid.
- **Single owner of the output layout.** sway-apps renders `output "<make model serial>" {mode, pos, scale, transform, adaptive_sync, enable|disable}` into its include, keyed by hardware id (connectors drift). nwg-displays' `~/.config/sway/outputs` is imported once and then no longer included (`include ~/.config/sway/outputs`, swayfx-config.nix:1363, goes; the "Open nwg-displays" button goes). **kanshi is removed on sway-apps machines** (Diego 2026-10-14): DESK and X13 run `kanshiImperativeMode` with `output * enable`, restarted by `exec_always` on every reload (swayfx-config.nix:898-905) and on each HM switch (kanshi.nix:40-47), which would undo any `disable` sway-apps writes seconds later. The enable policy moves into the include. X13's lid script keeps working (it calls swaymsg directly).

## 1. Tray watcher (SWAY-1) — prerequisite for §2

Waybar's SNI Watcher is a singleton destroyed on SIGUSR2 reload and restart (`bars.clear()`; src/main.cpp, src/client.cpp, sni/watcher.hpp in 0.14.0), so Electron items that never re-register vanish. New `sway-apps tray-watcher` (Gio D-Bus, pygobject is already a dependency): systemd user service `Type=dbus`, `BusName=org.kde.StatusNotifierWatcher`, `Before=waybar.service`. Implements RegisterStatusNotifierItem/Host, RegisteredStatusNotifierItems, IsStatusNotifierHostRegistered, ProtocolVersion, the four signals; drops items when their owner vanishes. Accepts object-path, well-known-name and combined `name/path` registrations (the case Waybar PR #5287 patches). Waybar then runs as host only. Bus-name ownership: Waybar owns with `ALLOW_REPLACEMENT|REPLACE` (sni/watcher.cpp:9-15), so ours requests `REPLACE` WITHOUT `ALLOW_REPLACEMENT` (else Waybar steals it on every start); Waybar's leftover skeleton on its unique name is harmless. Items never re-register, so at start-up the watcher adopts what is already on the bus (`ListNames` → `org.kde.StatusNotifierItem-*` and `org.freedesktop.StatusNotifierItem-*`; live DESK has electron + trayscale in the freedesktop form) — otherwise the first deploy or any watcher restart empties the tray. Waybar's Host re-registers on name_appeared and clears on name_vanished (sni/host.cpp:36-57). Units that wait for the tray (session-systemd.nix:118-146, 235-238) get `After=` the watcher. Done when Waybar restart, Waybar reload AND watcher restart on DESK keep every icon; only then trim `sync-posthook.sh:61`'s restart list (closes AINF-68).

## 2. Waybar (SWAY-2..5)

Decisions: Hyper+Shift+H toggles the focused monitor's bar; all-at-once via GUI/CLI only. Hotkey state is machine-local and survives reboots; the GUI can "save as default" into the profile JSON; "reset to default" drops the local state. Unregistered monitors share one catch-all bar, hidden by default. Workspaces widget: per bar "this monitor" (default) or "all"; when exactly ONE bar is effectively visible it shows all. Effectively visible = enabled AND output active AND its visible workspace has no fullscreen view. Tray on every visible bar. Size per monitor (one scale %). Widget templates: primary + secondary (shared), any monitor may override; default = today's bar.

Verified in nested headless sway 1.11 + waybar 0.14.0 (2026-10-14):
- `"ipc": true` + `"id"` per bar + sway `bar { id …; swaybar_command true; mode … }` → `swaymsg bar <id> mode dock|invisible` hides/shows ONE output's bar of a single Waybar process, no restart (workspace rect y 30→0→30). The 2026-09 memory saying sway bar mode does not drive Waybar was measured without `ipc: true`.
- `swaymsg reload` resends every bar's config-file mode → the generated sway bar include carries the persisted state.
- `all-outputs` is read once per module → "this monitor" = one module with `all-outputs: true` + CSS `window#waybar.<bar> #workspaces button:not(.current_output) {min-width:0; padding:0; margin:0; border:0; font-size:0; opacity:0}` — collapses with no gap. `reload_style_on_change` watches `@import`ed files (css_reload_helper.cpp) → applied < 1.5 s, no reload.
- Output matching supports `!name` and `*` (config.cpp isValidOutput) → catch-all bar. Bar windows carry output name + bar `name` as CSS classes (bar.cpp:149-150).

Design: Nix writes a module catalog `~/.config/sway-apps/waybar-modules.json` (every module definition with store paths, filtered by host flags: llm, gcal, battery…) and the static base CSS (`style.css` @imports `sway-apps.css`). sway-apps generates `~/.config/waybar/config` (HM stops managing it), `~/.config/waybar/sway-apps.css` (WS mode, effective-visibility, per-bar size), `~/.config/sway/sway-apps-bars.conf` (bar blocks + modes; replaces the two `bar` blocks at swayfx-config.nix:1345 and :1435, whose ids would otherwise collide). Visibility change → `swaymsg bar … mode`. WS mode / fullscreen / size → CSS rewrite, only when the rendered text changes (every gamescope start/stop flips effective visibility, and Waybar reparses the whole stylesheet on every bar per write — measure it). `CssReloadHelper` resolves symlinks once at start-up (css_reload_helper.cpp:48-57): `sway-apps.css` must be a regular file written atomically in place, and `style.css` must not be an HM store symlink (it goes stale after each HM switch) — sway-apps writes it too, from a Nix-provided base. Template or height/icon-size change → regenerate config + SIGUSR2 (safe after §1). The watch daemon recomputes effective visibility on workspace/window(fullscreen_mode)/output events, debounced.

## 3. Window stacking — local sway patch `patches/sway-window-stacking.patch` (SWAY-6, SWAY-7)

Applied after `sway-xwayland-zero-scaling.patch` and `sway-above-fullscreen.patch` in the same overlay (`lib/flake-base.nix`, system + HM + nixpkgs-patched, as the existing ones). Feature flag `swayWindowStacking` in `lib/defaults.nix` (false), true on DESK and X13.

- Floating above tiles: sway's native model (floating scene layer above tiling); nothing to build. AkuWM needs a TOPMOST band + 300 ms re-raise only because Win32 lets a clicked tile come up.
- **Peek** (as AkuWM 034c23a): button down (left or right) on a TILE that a float overlaps → the tile is drawn above the floating layer until that button is released; no delay, no modifier; Alt (floating_modifier) drag/resize untouched; one lifted tile at a time. NOT a one-shot reparent: every transaction re-parents tiles into `ws->layers.tiling` (transaction.c:314-379, 558) and the lifting click itself focuses the tile and commits one. So: new `root->layers.lifted` between `floating` and `shell_top` (root.h:40-55); `arrange_children` skips the lifted con and places it like a floater (reparent + `set_position(current.x, current.y)` in layout coords). Release in `seatop_down`'s `.end` (seatop_down.c:205-208), which `seatop_end` runs on every exit path (release, surface destroy, unref, touch/tablet up, another seatop starting) — not in handle_button. `seatop_down` only starts on CONTENT presses; titlebar presses go through seatop_default, so peek does not fire on titlebars (documented, acceptable: the titlebar of a covered tile is under the float anyway in most layouts). Fullscreen exclusion is natural (`disable_workspace`, transaction.c:551-567). Command `lift_tiled_on_press enable|disable` (config + runtime).
- **Pin** (floating only): `pin enable|disable|toggle`; pinned band = tail of `ws->floating`. Implemented INSIDE `container_raise_floating` (10 callers: commands/focus.c:398/469, seatop_down/move_floating/resize_floating/move_tiling, tree/root.c:203, tree/view.c:425/438/685) and `workspace_add_floating` (workspace.c:818 appends at the end — sticky floats re-added on every workspace switch would land above pinned ones); `arrange_workspace_floating` re-raises the scene nodes in list order at the end (`wlr_scene_node_reparent` is a no-op when the parent is unchanged, so list and scene order would drift). Pinning a tiled window is refused with an error. Sticky + pinned works. get_tree exposes `pinned`.
- **Above fullscreen is a separate per-window switch** (Diego 2026-10-14), not implied by pin: the existing `above_fullscreen` command, exposed in sway-apps per window/rule. Pinned+above_fullscreen windows keep their pin order over the game. Cost noted in the GUI (AkuWM measured 45 fps / +60 ms on Aion 2 for an overlay over a game).
- **Floating geometry IPC events** (needed by §5, replaces any polling): `seatop_move_floating`, `seatop_resize_floating` and the `resize` command emit nothing today; only `move` paths emit `window:move` (commands/move.c:234/264/771). The patch adds `ipc_event_window(con, "move")` at the end of those two seatops and in `resize`.
- **z raise|lower**: one step within the window's band; bottom stays bottom (never behind tiles). Bound to `$hyper+button4/button5 --whole-window` (mouse bindings act on the container under the cursor).
- sway-apps: pin toggle shortcut (free combo from `sway-apps shortcuts free`), rule action `pin` ("always pin this app", GUI), peek on/off setting → include line.

## 4. Monitors view + scale picker (SWAY-8, SWAY-9)

- GUI canvas draws active outputs to scale (logical rects, transform applied), with role, name, mode, scale, primary, visible workspace and bar area; drag to arrange (snap edges, no overlap, no gaps allowed only if Diego wants them), pick mode/refresh/transform/adaptive sync. "Apply" = live `swaymsg output …` + write the profile JSON + regenerate include; "Revert in 15 s unless confirmed" like display dialogs (a bad scale/mode must not strand him). AkuWM's view is read-only (Canvas + table); this goes further, closer to nwg-displays.
- **Exact scales**: Wayland fractional scale is in 1/120 steps (wp-fractional-scale-v1), so candidates are k/120 with logical width AND height integral for the native mode (after transform). Examples: 3840x2160 → 1.2 (3200x1800), 1.25 (3072x1728), 1.5 (2560x1440), 1.6 (2400x1350), 1.875 (2048x1152), 2; 1.4 → 2742.86 (not exact). 2560x1440 → 1.25 (2048x1152), 1.6 (1600x900), 2; 1.1 not exact. Picker lists exact ones; "forced" scale is allowed behind a warning: gamescope and fullscreen apps get rescaled, some apps render blurry.
- **X11 DPI**: one value for all of Xwayland (`xwayland_dpi`, config-only, registered in config_handlers by our patch, applied in handle_xwayland_ready; `swayXwaylandDpi` = 144 today = 96 × 1.5). When the PRIMARY monitor's scale changes, offer to set DPI = round(96 × scale) (1.6 → 154, 1.25 → 120) so Steam and the meter keep their size; written to the include, then `swaymsg reload`. It takes effect only when Xwayland next starts: Xwayland lives while ANY X client does, so with Steam open the GUI must say "applies after Steam/X11 apps close". The Nix value becomes the default only. **`swayXwaylandZeroScaling` becomes on for every sway profile we own** (Diego 2026-10-14): enable it on X13 too (wlroots + sway rebuild there); the include only emits `xwayland_*` lines when that flag is on, otherwise validation fails.
- **Revert timer**: a mode/scale/position change is applied live only; the profile JSON and include are written after "Keep" is pressed. A crash or timeout reverts to the last saved layout.

## 5. Window persistence (SWAY-11)

Live (on every `window` event: new, move — including the floating move/resize events added by the §3 patch, so no polling — floating, fullscreen_mode, close) the journal records per app identity (`app_id`, or `window_properties.class` for X11; optional title regex from rules): workspace, floating, floating rect relative to its output (and the output's role), output role. Restore on `window new` for that identity: workspace, floating state, size clamped to the output, position clamped inside (AkuWM AppMemory rules). Not applied when a sway-apps rule already places the app (rules win), for fullscreen-born windows, dialogs/transients, sticky/pinned windows, games (gamescope, steam_app_*), or excluded app ids (GUI list). Multi-instance: the record follows the last window of the app that changed; a second instance opening while the first is alive gets size only (no stacking on top). Global on/off + per-app forget, in the GUI. Machine-local file. Debounced write (≥ 1 s, only on change). `window:new` arrives before the first frame: apply `floating enable, resize set W H, move position X Y` as ONE command on `[con_id=…]`. Electron/GTK apps that restore their own geometry will fight once on first map; if that shows, add a per-app "let the app place itself" exclusion.

## 6. Bring windows (SWAY-10)

- **Bring off-screen** (shortcut): floating windows whose overlap with every active output is < 24 px in either axis (AkuWM's number, Diego's) move into the focused output, size kept, trimmed only if larger than the output. Tiles are never off-screen in sway.
- **Bring all** (shortcut), AkuWM `fetch-windows` semantics: a toggle. First press lends every window of the OTHER outputs' workspaces to the focused output's visible workspace (floats mapped absolute/clamped, tiles appended); second press returns each one that is still where the loan put it ("anything else was the person's doing since, and stands"). Loans also return automatically when the screen they came from is replugged (AkuWM). A fullscreen window lent away is floated while away and goes fullscreen again when it is back (AkuWM).

## 7. Monitor power-off policy (SWAY-12)

Global default + per-monitor override, GUI; the policy is read at the moment it is needed, not cached (AkuWM). Inputs: `output` IPC events fire only on enable/disable/destroy (desktop/output.c:392); DPMS emits nothing. **ignore** = sway-apps adds nothing: with the existing `always_connected` DRM connector force (already on for the Samsung in apps/DESK.json) a sleeping panel never disappears and nothing moves; if the output IS removed or disabled, sway itself moves its workspaces to another output (unavoidable: a workspace cannot stay on a disabled output, but they stay whole and reachable by number) and sway-apps' existing apply_live sends them home when it returns. **X13 lid while docked** (lid script disables eDP-1, swayfx-config.nix:1623+) is just the internal panel's per-monitor policy; Diego's choice for it: ignore. | **move windows** (let the output go; after a 5 s grace, if at least one output is still active, lend its windows to the focused remaining output's visible workspace; when it returns, restore the ones still where the loan put them, AkuWM `restore` rule). sway itself moves a removed output's workspaces to another output immediately — the policy works on top of that (record the snapshot from the last known tree before removal, i.e. the daemon keeps a rolling copy of the tree per output). All outputs gone → do nothing (AkuWM test "every screen gone lends nothing"). Never snapshot while an output is missing ("recording a layout with a monitor missing would memorise exactly the damage"). Wait for the hotplug burst to settle (AkuWM: 2 s for a change of shape, 6 s while a screen is missing during resume; sway's numbers to be measured here). A monitor back at a different mode: floats keep their position as a fraction of the output and their size. Cascade (host also leaves) lends on.

## 8. Driven e2e suite (SWAY-13)

`sway-apps-e2e` (script in the repo, tools declared in Nix: the patched sway, waybar, wlrctl, grim, jq): nested headless sway (pixman, 2–3 outputs via `create_output`/`WLR_HEADLESS_OUTPUTS`, own `XDG_RUNTIME_DIR` socket names, private D-Bus via `dbus-run-session`), real sway-apps against a scratch state dir. Asserts through IPC (rects, get_tree flags), wlrctl clicks/wheel, grim crops for visual checks. Prereqs: `SWAY_APPS_E2E=1` + connector fallback (§0); nested Waybar needs the nested WAYLAND_DISPLAY/SWAYSOCK and `GDK_BACKEND=wayland`; wlrctl (nixpkgs 0.2.2) added to the declared tools. Poll IPC with timeouts, never fixed sleeps. Cases: per-bar visibility + reload persistence, WS modes and auto-all with fullscreen, tray survives Waybar reload (fake SNI item in Python), peek (press-hold-release), pin band and z raise/lower, bring off-screen / bring all toggle, persistence restore after relaunch, power-off move + restore (output disable/enable on headless), exact-scale list. Budget: < 3 min total; runs on demand or after many changes; unit tests (`tests/test_*.py`, ~seconds) stay per change. Never touch the live session (separate sockets; pids recorded and killed by pid; never `pkill -f`).
