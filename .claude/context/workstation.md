## Docker here is rootless (DESK and LAPTOP_X13 since 2026-10-14, AINF-407)
`docker` / `docker compose` talk to the user's rootless daemon (`DOCKER_HOST=unix:///run/user/1000/docker.sock`, data in `~/.local/share/docker`). The root daemon exists only as `sudo docker` and only for the closed list: capturing host interfaces (`--net=host` + NET_RAW/NET_ADMIN), containers that manage host networking, undelegable devices. Ports < 1024, bind-mount permissions or "it worked before" are NOT reasons for root — adapt the stack first, then note in the project's memory that it runs rootless and what changed. Plan + full fix list: `~/.dotfiles/docs/akunito/plans/docker-rootless-workstations.md`.
- Named volume empty / DB looks fresh → data is still in the root daemon. Copy (Diego approves the sudo): `sudo docker run --rm -v VOL:/from alpine tar -C /from -cf - . | docker run --rm -i -v VOL:/to alpine tar -C /to -xpf -`.
- Bind mount `permission denied` → container uid maps to a subuid (container 1000 = host 100999). Dev containers writing into the source tree (Rails `tmp/`/`log/`, Vite): `user: "0:0"` — container root IS akunito, files stay owned by akunito (verified leftyworkout 2026-10-14). Service-uid data dirs (postgres 999 → host 100998): `sudo chown -R 100998:100998 DIR` once, after a backup.
- Not reachable from phone/LAN/tailnet → `-p 3110:3110` binds 127.0.0.1 on purpose. Publish on this machine's tailscale IP (DESK `100.64.0.5`, X13 `100.64.0.8`): `100.64.0.5:3110:3110`. Never `0.0.0.0`.
- Container can't reach a host service on `localhost`/`host.docker.internal`/10.0.2.2 → host loopback is closed on purpose; publish that service explicitly.
- App sees 127.0.0.1/10.0.2.100 as client IP → rootlesskit 2.x limitation. `--net=host` = the rootlesskit namespace, not the host's interfaces.
- A deploy that changes the rootless daemon config restarts `docker.service` only if no rootless container runs; otherwise it warns and the old config stays until `systemctl --user restart docker`.
- zsh gotcha (the Bash tool runs zsh): `-v $D:$D:ro` expands `$D:r` as a history modifier → mount lands at `…o`. Always `"${D}:${D}:ro"`.
- `--runtime krun` (crun + libkrun) runs a container in its own KVM microVM (guest kernel 6.12.91, VMM as subuid 100999, ~87 MB RSS); used by the REA sandbox (AINF-408), available for any untrusted image.

## Keep the desktop clean (2026-10-16)
Anything that would open a window on the real `$DISPLAY`/`$WAYLAND_DISPLAY` (WINE/Proton console apps, GUI tools, interactive TUIs) runs hidden on a throwaway X server: `Xvfb :99 -screen 0 1280x800x24 -nolisten tcp &`, wait for `/tmp/.X11-unix/X99`, run with `env -u WAYLAND_DISPLAY DISPLAY=:99 …` (GTK/Qt prefer Wayland while `WAYLAND_DISPLAY` is set and would land on the real desktop), then kill it and `rm -f /tmp/.X99-lock`. `Xvfb` is on PATH (`/run/current-system/sw/bin/Xvfb`, xorg-server's build — verified working 2026-10-16; the first recipe globbed the dedicated `xvfb` package in `/nix/store`, which only `user/app/rea/vm.nix` references; both work). Long or detached work: `setsid … &` with output to a log file, then poll the file.
